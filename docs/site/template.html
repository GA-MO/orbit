Not a chat app for talking to an AI. A remote for your own machine.

The MacBook holds everything

Files, git, tools and every agent stay on your machine. Nothing syncs anywhere, and there is no account to sign up for.

Sessions outlive the screen going dark

Close the browser, switch apps, lose the connection. Come back and the work is still running, with the scrollback replayed.

The same terminal, on a smaller screen

ANSI colour, TUIs, prompts that need an answer, Ctrl+C. Nothing is reformatted into pretty text on the way to your hand.

A clear line: Orbit does not replace the agent and writes no code itself. It makes an agent built for a 27-inch screen usable on the 6-inch one in your hand.

Open the address on your phone. That is the whole of it.

No token to type, no code to scan, nothing that quietly expires while you are away from the desk. Three things have to line up, and Tailscale does two of them.

Reaching the address means being one of your own devices

The server binds 127.0.0.1 alone, so tailscale serve is the only way in from anywhere else.

Tailscale stamps a verified login on the request

Every proxied request carries a Tailscale-User-Login header, so the phone arrives already named.

Orbit admits exactly one login

The one that owns the Mac it is running on. Another person on the same tailnet is still a stranger.

The escape hatch: orbit start --lan opens the wi-fi door for a Mac with no Tailscale. There the access token is the only credential and the header counts for nothing — because anyone who could reach the port could have written it.

The login page is the only screen that asks you for anything, and over your tailnet you never meet it.

Sessions

Approvals

A command that can destroy something goes through your finger first

Anything pasted, spoken or sent by automation is screened at the server against the same patterns used on the agent's own commands — deleting a folder whole, escalating to root, force push, raw disk writes.

A match holds the command and shows it to you in full. The first option is always the safe one, and no answer means no.

Let the agent see its own work, and reach you

So far the phone has been driving the Mac. These five tools are the other direction — the MCP server that ships with Orbit, called by the agent in the session.

orbit_capture

Renders the web app already running and hands the image back. The image, not a path.

orbit_screen

Captures the real Mac screen — Simulator, Xcode, anything headless Chrome cannot see.

orbit_preview

Opens the running app on your phone at the page the agent names, for you to tap.

orbit_notify

Sends a short message to your phone. "Done", or "Waiting on you."

orbit_ask

Puts a question on your phone and waits until someone taps an answer.

You find out when it is waiting on you

Claude Code draws its question box in the terminal and nowhere else, and will wait all night. The hooks send that moment to your phone.

A locked phone still gets the message

iOS drops the socket when the screen locks. Orbit keeps the message for the next device that connects, and Web Push wakes a phone with the app fully closed.

Silence while you are already looking

Every message from a hook is sent quiet. With Orbit open on screen nothing pops up at all.

It controls your personal computer, so this comes first

Bound to localhost

The server listens on 127.0.0.1, which leaves the tailnet proxy as the only way in — and that is exactly the condition under which the verified login header means anything. With --lan the header is ignored outright and the token becomes the only credential.

No token in a URL, ever

Where a token is still used it lives in ~/.orbit/config.json and travels as an Authorization header, never in a URL that would land in a proxy log or browser history. The socket and <img>, which cannot carry a header, use an HttpOnly cookie holding a hash of it that permits reads only.

Two gates, two sources

What you paste is screened at the server. What the agent runs through its Bash tool is screened by a second hook, against the same patterns. The two paths do not share code.

Nothing exposed to the internet

Tailscale builds a private network between your own devices: no router port to open, no DDNS, and no public address for anyone to find by scanning.

Boundaries enforced in code

A session can only start in a folder under your home. Publishing a port needs something already answering HTTP on it. A path the agent sends must be a path on this host.

From zero to driving it from your phone

One executable from a GitHub release, checksum verified before it installs. orbit setup is safe to run again at any time. 

# Once per machine — one file, no runtime to install
curl -fsSL https://raw.githubusercontent.com/GA-MO/orbit/main/install.sh | bash
orbit setup       # register the MCP server + install the Claude Code hooks
orbit start       # run on :7788 + Tailscale HTTPS, then open the address on your phone

# The rest of the surface
orbit stop        # the server, and the tailnet front door with it
orbit doctor      # what this Mac has, and what it is missing
orbit update      # replace this executable with the latest release
orbit pair        # a QR + token, for the wi-fi path
orbit start --lan # no Tailscale? open the wi-fi door instead
What you need

macOS on Apple silicon or Intel, Claude Code on PATH, Chrome for captures, and Tailscale on both the Mac and the phone.

What happens on first run

orbit start prints the tailnet address. Open it on your phone and you are in. On the --lan path it prints a token instead.
