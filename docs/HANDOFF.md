## 1. session ที่เงียบไปเฉย ๆ — Orbit เห็นเองแล้ว

ช่องทาง Mac→phone ทั้งหมดที่มีอยู่คือ agent **เลือกที่จะพูด**: `orbit_notify` ผ่าน MCP หรือ hook
ของ Claude Code ทั้งคู่ทำงานดี และทั้งคู่ต้องมีคนไปตั้งไว้ก่อน Codex, Gemini, shell ไม่มีสักอย่าง
Claude ที่ยังไม่ได้ลง hook ก็ไม่มี — มือถือจึงเงียบสนิทตอนที่ terminal นั่งค้างอยู่ที่ "Do you want
to proceed?" ซึ่งเป็นนาทีเดียวที่แอปนี้มีไว้เพื่อมัน

**สตรีมมันบอกอยู่แล้ว** agent ที่ทำงานคือ agent ที่วาดจอ — สปินเนอร์ ตัวนับวินาที ผลของ tool
ทุกอันรีเพนต์หลายครั้งต่อวินาที ความเงียบบน PTY จึงไม่ได้แปลว่า "ยุ่งแต่เงียบ" แต่แปลว่าเฟรมบนจอ
วาดจบแล้ว นี่คือสัญญาณที่ไม่ต้องไปแกะ UI ของ agent ตัวไหนเลย และไม่ต้องตามแก้ตอนใครสักตัว
ออกแบบหน้าจอใหม่ (`server/src/idle.ts`)

ตัวเลขที่เลือกไว้ และเหตุผล:

- **10 วินาที** ก่อนนับว่าเงียบ — ต้นทุนของการรอคือป้ายที่ขึ้นช้าไปสิบวินาทีบนมือถือที่ยังไม่มีใคร
  หยิบ ต้นทุนของการใจร้อนคือบอกว่า "รออยู่" กลางการรัน tool ที่บังเอิญไม่ได้วาดอะไร ซึ่งสอนให้
  ผู้ใช้เลิกเชื่อป้าย
- **200 ตัวอักษร** ขั้นต่ำต่อเทิร์น — terminal echo สิ่งที่พิมพ์ ทุกคีย์คือ output ไม่กี่ไบต์
  ถ้าไม่มีพื้น การเปิด session ทิ้งไว้เฉย ๆ จะประกาศตัวเองว่ารออยู่ในสิบวินาทีถัดมา
- **รอบละครั้ง** — คีย์ถัดไปคือสิ่งที่ arm ใหม่ อย่างเดียวที่ช่องทางแจ้งเตือนห้ามทำคือพูดซ้ำ
  ทั้งที่ไม่มีอะไรเปลี่ยน
- **เฉพาะ session ที่เป็น agent** (`provider.command`) — shell ที่นั่งอยู่ที่ prompt เงียบตั้งแต่
  วินาทีแรก ถ้านับด้วยคือติดป้ายทุกแถวแล้วไม่ได้แปลว่าอะไร

**บรรทัดที่เอามาโชว์** เป็น best effort และทุกชั้นที่รับต่อก็ปฏิบัติกับมันแบบนั้น — ของที่ต้องถูก
คือ *แถวไหน* ที่รออยู่ ไม่ใช่ประโยคใต้แถว เลือกโดยตัด ANSI/OSC/กรอบกล่องออก ทิ้งบรรทัด chrome ที่
agent วาดค้างไว้ตลอด (`? for shortcuts`, `⏵⏵ accept edits on`, `esc to interrupt`) แล้ว**เลือก
บรรทัดที่ลงท้ายด้วย `?` ก่อนบรรทัดสุดท้าย** เพราะบรรทัดสุดท้ายของ agent ที่หยุดคือช่องพิมพ์ของมัน
ส่วนสิ่งที่มันหยุดรออยู่สูงกว่านั้นหนึ่งหรือสองบรรทัด

**ลำดับความสำคัญ** สิ่งที่ agent พูดเองชนะเสมอ — `attention.raiseIdle()` ไม่เขียนทับอะไรที่มีอยู่
แล้ว และในทางกลับกัน `raise('done')` ที่เคยถูกห้ามทับ `'waiting'` ตอนนี้ทับได้ถ้าอันเดิมเป็นการเดา
(`idle: true`) เพราะกฎที่คุ้มครอง 'waiting' มีไว้คุ้มครอง *คำถามจริง* ไม่ใช่บรรทัดที่ขูดมาจากจอ

**ใครถูกรบกวน** เรียงตามราคาที่ผู้ใช้จ่าย: กำลังเปิดดู session นั้นอยู่ → ไม่ทำอะไรเลย (จอที่ขูด
มาคือจอที่เขามองอยู่), agent พูดไปแล้ว → คำพูดเดิมยืน, มีมือถือต่ออยู่ → ได้ frame `attention`
เงียบ ๆ ให้ไป refresh ป้าย (**ไม่ใช่ notice** — ถ้าเป็น toast ทุกครั้งที่ agent จบเทิร์น สาม
session พร้อมกันคือแอปที่ใช้ไม่ได้), ไม่มีมือถือเลย → push `"<ชื่อ> is waiting"`

ฝั่งหน้าเว็บ: ป้ายที่มาจากการเดาใช้สีจางและ**จุดไม่กระพริบ** — มันแปลว่า "อันนี้ต้องการเรา" เท่ากัน
แต่เหตุผลเป็นการเดา คนอ่านควรแยกออกจากคำพูดจริงโดยไม่ต้องเปิดเข้าไปดู

## 2. ตอบคำถามจากตัว notification

push ปลุก service worker ตอนแอปปิดสนิท — ซึ่งเป็นเหตุผลที่มันมีอยู่ — และ worker ตัวนั้น **ไม่มี
token** โดยตั้งใจ: สคริปต์เบื้องหลังที่มีสิทธิ์ถาวรทำได้ทุกอย่างที่มือถือทำได้ เป็นของที่แย่กว่า
การกดสี่ที ที่ให้แทนคือ **capability**: คำถามนี้ คำถามเดียว ตอบด้วยตัวเลือกที่คำถามนั้นประกาศไว้
ได้ครั้งเดียว (`notify.answerWith`)

- `notify.ask()` มี `announce` callback ที่ยิงหลังลงทะเบียนคำถามและก่อน broadcast — push ที่จะ
  ประกาศคำถามต้องเรียกชื่อมันได้ และไม่มีอะไรเรียกชื่อสิ่งที่ยังไม่มีตัวตนได้
- payload ของ push พก `{ask: {id, token, options}}` → `sw.js` วาดตัวเลือกสองอันแรกเป็นปุ่มบน
  แบนเนอร์ (`tag: 'orbit-ask'` แยกจาก `orbit-notice` — คำถามกับ notice ทับกันไม่ได้ มีอันเดียว
  ที่ยังรออยู่)
- `POST /api/ask/answer` เป็น**เส้นทางเดียวที่ access token ไม่ได้เฝ้า** ด่านอยู่ที่ nonce 24 ไบต์
  เทียบแบบ constant-time, ตัวเลือกต้องอยู่ใน `ask.options` (นี่คือสิ่งที่กันไม่ให้ capability
  พิมพ์อะไรก็ได้ใส่ agent), ใช้แล้วหมด, หมดอายุพร้อมคำถาม nonce ผิด/คำถามปิดแล้ว → 404 หน่วง
  ตามจังหวะเดียวกับ token ผิด
- iOS ไม่แสดงปุ่มบน web push — เคสนั้นถอยลงมาเป็นพฤติกรรมเดิมเป๊ะ ๆ คือแตะแล้วเปิดคำถามในแอป
- Mac ติดต่อไม่ได้ตอนกดปุ่ม → worker เด้งแบนเนอร์บอกว่าส่งไม่ได้ แทนที่จะกลืนการกดนั้นไปเงียบ ๆ

## 3. `tailscale` ปลอม — เทส preview ที่รันจริงและไม่ทิ้งอะไรไว้

section `previews` ใน smoke เคยรันกับ CLI จริง หรือไม่ก็ **ถูกข้าม** บนเครื่องที่ไม่มี Tailscale /
ล็อกเอาต์ (แปลว่าบน checkout ใหม่ไม่เคยพิสูจน์อะไรเลย) และบนเครื่องที่มันได้รันจริง มัน publish
mapping จริงลง tailnet จริง — หนึ่งในนั้นคือ `:8443 → 127.0.0.1:3099` ที่อยู่ยืนยงกว่า server
ทิ้งขว้างที่มันชี้ไป และไปหลอกคนดีบักอีกหลายสัปดาห์ต่อมา (บันทึกไว้ในรอบก่อนหน้าใน HANDOFF นี้เอง)

`ORBIT_TAILSCALE` ชี้ `preview.ts` ไปที่ `scripts/fake-tailscale.mjs` ได้ ซึ่งตอบ 4 คำสั่งที่โมดูล
นั้นเรียก เก็บ mapping ไว้ในไฟล์ JSON ใต้ HOME ของเทสเอง และไม่แตะเน็ตเวิร์กเลย มันเป็นตัวแทนของ
*CLI* ไม่ใช่ของ Tailscale — สิ่งที่พิสูจน์ได้คือ Orbit อ่าน `serve status --json` เป็น, เลือกพอร์ต
สาธารณะที่ว่างเป็น, รู้จักประตูหน้าโดยไม่มีใครบอก (seed ไว้ที่ `443 → 3001` เหมือนของจริงที่
`make phone-on` วางไว้ก่อนแล้ว) และเอา mapping ลงเป็น ส่วน tailnet จะส่งทราฟฟิกจริงไหมไม่ใช่คำถาม
ที่เทสบนเครื่องเดียวตอบได้ ตั้ง `ORBIT_TAILSCALE` เองก่อนรัน `scripts/test.sh` ถ้าอยากยิงของจริง

ผลพลอยได้: **`POST /api/preview` มีเทสแล้ว** (ของที่ค้างจากรอบก่อน) — ด่าน HTTP probe บนพอร์ต,
path ที่กลายเป็นส่วนหนึ่งของ URL, `//evil.com/x` ที่ต้องอยู่บน host เรา, URL เต็มที่ต้องโดนปฏิเสธ,
พอร์ตที่ไม่มีอะไรอยู่/ตอบแต่ไม่ใช่ HTTP, และเคส "ไม่มีมือถือต่ออยู่" ที่ต้องถอยเป็น notice บอกพอร์ต
กับ path

  ผิด, token ยาวเท่ากันแต่ผิด, คำถามที่ไม่มีจริง, ตัวเลือกที่คำถามไม่ได้ประกาศ, ใช้ซ้ำ, ตอบหลัง

## 1. Preview พังถาวรถ้า Tailscale ขึ้นช้ากว่า Orbit

`preview.ts` แคชผลการหา `tailscale` และชื่อ tailnet ไว้ในตัวแปรระดับโมดูล ซึ่งถูก — ทั้งคู่
ไม่เปลี่ยนระหว่าง server ทำงาน และแต่ละครั้งต้องเปิด process แต่มัน **แคชความล้มเหลวด้วย**
`return (cli = null)` และ `return (host = null)` แปลว่า server ที่สตาร์ตตอน Tailscale ยังไม่ขึ้น
หรือยังไม่ล็อกอิน (เรื่องปกติหลังบูต) จะตอบ "tailscale is not logged in" ไปตลอดอายุ process
และทางแก้เดียวคือรีสตาร์ต — ซึ่งเป็นสิ่งที่ราคาแพงที่สุดในโปรเจกต์นี้ เพราะมันฆ่า session ที่
กำลังทำงานอยู่

ตอนนี้แคชเฉพาะผลบวก ส่วนผลลบเก็บเป็น timestamp แล้วลองใหม่ได้หลัง 30 วินาที — ตัวเลขนี้ไม่ใช่
ความระมัดระวังลอย ๆ `state()` ถูกเรียกทุกครั้งที่โทรศัพท์กลับมาหน้าจอ และ liveness poll ทุก 10
วินาที ถ้า retry แบบไม่มีเพดานคือเปิด process ทิ้งทั้งวันเพื่อถามสิ่งที่แทบไม่เคยเปลี่ยน

เคสที่โผล่มาระหว่างทาง: `DNSName` ที่เป็นสตริงว่างก็เคยถูกแคชถาวรเหมือนกัน ตอนนี้นับเป็นความ
ล้มเหลว ไม่ใช่คำตอบ

## 2. `orbit_preview` — agent พูดว่า "ไปดูอันนี้สิ" ได้แล้ว

MCP มี `orbit_capture` ให้ agent ดูงานตัวเอง และ `orbit_notify` ให้บอกว่าเสร็จ แต่ไม่มีอะไรที่
ส่ง *แอปที่รันอยู่* ไปให้คนถือโทรศัพท์ ก่อนหน้านี้ต้องเปิดแท็บ Preview เอง หาชิป port เอง กด
Share เอง แล้วแตะแถวเอง — และ preview ที่ publish แล้วลงที่ `/` เสมอ ทั้งที่หน้าที่อยากดูคือ
route ที่ agent เพิ่งแก้

เส้นทางทั้งเส้น: `orbit_preview({ port, path? })` → `POST /api/preview` → `preview.start()`
(idempotent อยู่แล้ว) → ต่อ path → broadcast `{type:'preview'}` บน WebSocket เดิม →
`Terminal.tsx` ส่งขึ้น `App.tsx` → `App` เปิด `PageViewer` เอง **จาก App ไม่ใช่จากแท็บ Preview**
เพราะแท็บที่อยู่ข้างหน้าตอน agent พูดแบบนี้เกือบทุกครั้งคือเทอร์มินัล

`start()` ไม่ถูกเปลี่ยนสัญญา — สิ่งที่ publish คือ *port* ไม่ใช่ path ส่วน path ต่อโดยผู้เรียก

**ไม่มีช่องพิมพ์ path บนมือถือ และจะไม่มี** การพิมพ์บนคีย์บอร์ดจอสัมผัสคือปัญหาที่ชิป port
เกิดมาแก้ path มาจาก agent ทางเดียว

### ด่านกรอง path (`preview.previewUrl`)

นี่คือด่านเดียวระหว่างสตริงที่ agent เลือกกับ URL ที่โทรศัพท์เปิด อยู่ใน `preview.ts` เพราะมัน
เป็นเรื่องรูปร่างของ URL ล้วน ๆ ไม่เกี่ยวกับ HTTP — และเพราะแบบนั้นถึงเทสได้โดยไม่ต้องมี server

- อะไรที่มี scheme (`http://`, `javascript:`, `data:`) → **ปฏิเสธ 400** ไม่ใช่ดัดให้เป็น path
  agent ที่ส่ง URL เต็มมาคืออ่านอาร์กิวเมนต์ผิด การบอกตรง ๆ สอนมันมากกว่าการเปิด `/http:/evil.com`
- `//evil.com/x` และ `\\evil.com` → ปอก slash/backslash นำหน้าทั้งหมดแล้วใส่คืนอันเดียว
  กลายเป็น path บน host เรา ไม่มีที่ให้ host แอบ
- `..` → ปล่อยให้ `new URL` clamp ที่รากแบบเดียวกับเบราว์เซอร์
- query string กับ fragment รอด เพราะ route ที่อยากโชว์มักเป็น `/orders?status=open`

`scripts/preview-url-smoke.mjs` (ใหม่, `make test-preview-url`) 17 เคส รันตรงด้วย `node` ไม่ต้อง
มี server ไม่ต้องมี tailscale

### ตอนไม่มีมือถือต่ออยู่

`openPreview()` **ไม่** เข้าคิว missed โดยตั้งใจ — frame ที่เปิดย้อนหลังหนึ่งชั่วโมงคือภาพที่
*ผิด* ไม่ใช่ภาพที่เก่า สิ่งที่เก็บแทนคือ notice ("Wanted to show you port 5173 at /settings")
ผ่านคิว missed + push ชุดเดียวกับ notice ปกติ ซึ่งอ่านทีหลังแล้วยังมีความหมาย

## 3. agent publish ได้เฉพาะสิ่งที่ตอบ HTTP จริง

การเอา port ขึ้น tailnet เคยเป็นการกดด้วยนิ้วเสมอ route นี้ทำให้ agent ทำเองได้ — และ
`orbit_preview(5432)` ก็จะเอา Postgres ขึ้น tailnet ได้ ความเสี่ยงจำกัด (`tailscale serve`
เป็น tailnet-only ไม่ใช่ `funnel` และ `stopAll` เก็บกวาดตอนปิด) แต่การตัดสินใจย้ายจากคนไปอยู่ที่
agent ซึ่งเป็นคนละเรื่องกัน

`ports.ts` ตอบคำถามนี้อยู่แล้ว — `speaksHttp` คือฟิลเตอร์ตัวที่สามของลิสต์ชิป จึง export มาใช้ซ้ำ
ไม่เขียนใหม่ ถามก่อนแตะ `tailscale serve` เลย การปฏิเสธที่ยังไม่ได้ publish อะไรคือสิ่งที่ agent
เอาไปแก้ได้ทันที

**ตรงนี้ทางของ agent แยกจากทางของมือถือโดยตั้งใจ**: `preview.start` ยัง publish port ที่ยังไม่มี
อะไรฟังอยู่ได้ เพราะคนที่กดชิปมักเร็วกว่า vite หนึ่งวินาที และแถวบอกเขาว่า "ยังไม่มีอะไรตรงนั้น"
แล้วเขารอเองได้ ส่วน agent ไม่มีแถวนั้น มันโยน URL เข้า frame บนมือถือเลย และ frame ว่างแยกไม่ออก
จากแอปพัง `preview.start` ไม่ถูกแตะ

## 4. resume แทนที่แถวเดิม ไม่ใช่เพิ่มแถวใหม่

`restart()` เรียก `create()` ซึ่งได้ session id ใหม่และแถวใหม่ ส่วนแถว ended เดิมยังอยู่ กลไก
`claim` ใน `list()` กันไม่ให้บทสนทนาเดียวถูกเปิดสองที่ แถวเก่าเลยได้ `resumable: false` — **แต่มัน
ยังอยู่** resume ห้าครั้งได้หกแถวของบทสนทนาเดียว ห้าแถวเป็นทางตัน แต่ละแถวถือ scrollback แค่ท่อน
ของตัวเอง และทั้งหกกินโควตา `DEAD_SESSIONS_KEPT = 20` จน session เก่าที่มีค่าจริงถูก prune ทิ้ง

ที่ทำให้มั่นใจว่านี่คือบั๊กไม่ใช่ดีไซน์: บทสนทนาจากเทอร์มินัลบน Mac **แทนที่อยู่แล้ว** —
`discover()` กรอง transcript ที่ถูก `conversationId` ของ session ไหนอ้างไปแล้วออก "resume =
แถวเดิมเดินต่อ" จึงเป็นกฎที่โปรเจกต์นี้เลือกไว้ก่อนแล้ว session ของ Orbit เองต่างหากที่ทำไม่เหมือน

ตอนนี้ `restart()` เรียก `forget(id)` **หลัง** `create()` คืน session สำเร็จเท่านั้น — launch ที่
ล้มเหลวไม่ควรกินทั้งแถวและประวัติไปด้วย ปุ่ม ＋ (`resume === false`) ไม่ถูกแตะ เพราะนั่นคือบทสนทนา
คนละอันจริง ๆ

แถว external ปลอดภัยโดยไม่ต้องเขียนเคสพิเศษ: `forget()` เริ่มด้วย `this.dead.delete(id)` ซึ่งเป็น
no-op สำหรับ transcript ที่อยู่ใน `this.external` ไฟล์ของ Claude Code ไม่ถูกแตะ แต่แถวหายไปเอง
เพราะ `discover()`

**ราคาที่จ่าย**: scrollback ท่อนแรกหายไป ประวัติบนจอเริ่มที่จุด resume ตัวบทสนทนาไม่หาย เพราะมัน
อยู่กับ `claude --resume` ทางเลือกอีกทางคือย้าย buffer เก่ามาต่อหัว แต่ scrollback ที่เย็บจากสอง
รอบของ agent อ่านยากกว่าอันที่เริ่มตรงจุดที่คนหยิบมันขึ้นมาใหม่

## 5. จับคู่ด้วย QR — token ไม่เคยอยู่ใน URL

`auth.ts` เขียนไว้นานแล้วว่า token ห้ามอยู่ใน URL: query string เขียนมันลง proxy log, referrer
และ history ทุกที่ที่ URL ผ่าน — และตอนนี้ Orbit ถูกเข้าถึง *ผ่าน* proxy จริง ๆ (`tailscale serve`)
QR ที่เข้ารหัสเป็น `https://host/?token=…` คือการรื้อกฎข้อนี้

ตัวที่ฆ่าไอเดียแบบง่ายกว่านั้นอีก: บน iOS แอปที่ Add to Home Screen มี storage **แยก**จาก Safari
สแกนด้วยแอปกล้อง → เปิดใน Safari → ล็อกอินสำเร็จผิดตัว เพราะ Orbit ต้องเป็น PWA ที่ติดตั้งแล้ว
push ถึงจะทำงาน

ทางที่เลือก: **QR บรรจุ token เปล่า ๆ ไม่ใช่ URL** และกล้องเปิด *ในแอป*

- `server/src/qr.ts` — `tokenQr()` พิมพ์ต่อจากบรรทัด `[orbit] access token:` เดิม (ซึ่งยังอยู่
  ครบ เป็นสิ่งที่คนก๊อป และเป็นสิ่งที่เอกสารชี้ไป) พิมพ์เฉพาะตอน `process.stdout.isTTY` — ต่อ
  ท่อลง log file แล้ว block ยูนิโค้ดคือขยะ
- `qrcode-terminal` โหมด `small` วาด module สว่างด้วยสี*ตัวอักษร* แล้วปล่อย module มืดเป็นสีพื้น
  ของเทอร์มินัล แปลว่าบนธีมสว่างมันกลับขั้วทั้งอัน และกล้องหลายรุ่นไม่อ่าน QR ที่กลับขั้ว จึง pin
  `\x1b[97;40m` ต่อแถว **บั๊กนี้จะโผล่เฉพาะบนเครื่องคนอื่น**
- quiet zone ในตัวของมันบางเกินไป (หนึ่ง module วาดครึ่งแถว) จึงถอดทิ้งแล้วสร้างใหม่เป็น 4 module
- `web/src/QrScanner.tsx` + ปุ่ม Scan บนหน้า Login — `jsQR` โหลดด้วย dynamic `import()` ตอนกด
  เท่านั้น (แยก chunk 47.5 KB gzip ไม่ติดไปกับ boot bundle) เพราะการล็อกอินส่วนใหญ่คือการวาง
- gate secure context ตามแบบ `speech.ts` — plain http บน LAN ใช้กล้องไม่ได้ ต้องบอกเหตุผล ไม่ใช่
  ปุ่มตาย — และแปล DOMException เป็นชื่อ setting ที่ต้องไปเปิด แบบเดียวกับที่ `speech.ts` ทำกับ
  ไมโครโฟน
- teardown: `stop()` ตัวเดียวเป็นทั้ง cleanup ของ effect, ทาง success และทาง catch รวมถึง stream ที่
  resolve หลัง sheet ปิดไปแล้ว กล้องที่ค้างบน iOS ไม่มีอะไรบอกว่าหน้ายังถืออยู่
- auto-submit: ใช่ กรอกแล้วต่อเลย token เป็น base64 สุ่มในช่อง password ให้ยืนยันด้วยตาก็ไม่ได้
  อะไร อ่านพลาดเสียแค่ error หนึ่งบรรทัดโดยที่ช่องยังแก้ด้วยมือได้

## 2. router เป็นตาราง ไม่ใช่โซ่ if

`handleAuthedApi` ยาว 600 บรรทัดและความถูกต้องของมันอยู่ที่ **ลำดับที่บังเอิญเขียน**:
literal path ต้องมาก่อน pattern ที่ match ได้เหมือนกัน route ใหม่ที่แทรกผิดบรรทัดคือ
บั๊กที่ตอบด้วย handler ผิดตัวเงียบ ๆ เพราะทั้งสองสาขาเป็นโค้ดที่ถูกต้องทั้งคู่

- `on('POST /api/git/commit', handler)` + `match()` ที่เทียบ **จำนวน segment ก่อน** →
  `/api/sessions` กับ `/api/sessions/:id` ชนกันไม่ได้อีกไม่ว่าจะเรียงยังไง
- `HttpError` + `bad()` แทน `return json(res, 400, …)` ทุกจุด และ `c.body()` แปลง JSON
  พังเป็น 400 ให้เอง — เดิมทุก route เขียน try/catch เดียวกันซ้ำ 11 รอบ
- `inRepo()` ครอบ route git ทั้ง 6: ตรวจ cwd ครั้งเดียว และแปล error ของ git เป็น 400
  ในที่เดียว
- พฤติกรรมเดิมทุกอย่าง — 106 ข้อเดิมผ่านหมดโดยไม่แก้เทสสักข้อ

## 3. ความแข็งแรงฝั่ง server

| จุด | เดิม | ตอนนี้ |
| --- | --- | --- |
| `readBody` | ไม่มีเพดาน — request ที่ไม่จบคือ string ที่โตจนหมด RAM | 1MB แล้ว 413 (route upload มีเพดาน 20MB ของตัวเองอยู่แล้ว) |
| `bearer()` | `===` บน token | `matches()` ใน `auth.ts` — `timingSafeEqual` แบบเดียวกับที่ cookie ใช้อยู่แล้ว |
| ws | `maxPayload` ปริยาย 100MB, ไม่บีบอัด | 1MB + `perMessageDeflate` (`threshold: 1024` — คีย์เดียวไม่ต้องผ่านตัวบีบ) replay scrollback 200KB ทุกครั้งที่ปลดล็อกจอคือของที่คุ้มบีบ |
| ทายรหัส | ตอบเร็วเท่าที่ loop ตอบไหว | หน่วง 401 หลังพลาด 10 ครั้ง/นาที **ไม่บล็อก** — `tailscale serve` proxy ทุกเครื่องมาจาก 127.0.0.1 การบล็อกคือวิธีล็อกเจ้าของออกจากบ้านตัวเอง |

## 5. stage ทีละ hunk + diff ระดับคำ

- `git.applyHunk()` → `git apply --cached [--reverse]` ผ่าน stdin **index เท่านั้น
  working tree ไม่ขยับ** ซึ่งคือทั้งหมดของการ stage ครึ่งไฟล์
- **patch ถูกประกอบใหม่ฝั่ง server** — มือถือส่งมาแค่ body ของ hunk ส่วนหัวที่ระบุ
  ชื่อไฟล์เขียนจาก path ที่ตรวจแล้ว hunk จึงลงได้เฉพาะไฟล์ที่ sheet เปิดอยู่ (เทสมีข้อ
  "a patch cannot smuggle in a second file")
- hunk ที่ไม่ fit แล้ว git ปฏิเสธด้วยคำของมันเอง — ไฟล์ขยับใต้ sheet ที่เปิดค้าง การ
  ดันลงที่อื่นคือการเดา
- **ปุ่มโผล่เฉพาะไฟล์ที่ split ได้จริง**: `M` เท่านั้น ไฟล์ใหม่/ลบ/rename/untracked เป็น
  การตัดสินใจระดับไฟล์อยู่แล้ว และ diff ที่ถูก truncate อาจโดนตัดกลาง hunk
- เหลือ hunk เดียว = ทั้งไฟล์ ปุ่มต่อ hunk หายไปเอง (แถวในลิสต์มีปุ่มนั้นอยู่แล้ว)
- sheet **ไม่ปิด** หลัง stage — stage ครึ่งไฟล์แล้วมักตามด้วยอีกครึ่ง
- diff ระดับคำใช้ `web/src/diff-words.ts` (`pair` / `compareLines`) ที่มาจากอีก session
  รอบเดียวกัน — `markHunk` ใน `ChangesView` เป็นตัวหา run ของ `-` ที่ตามด้วย run ของ
  `+` แล้วส่งให้มันตัดสิน

## 6. สานต่อ: session ที่ปักหมุด conversation ของตัวเอง

`claude --continue` / `codex resume --last` เปิด "บทสนทนาล่าสุด**ของโฟลเดอร์**" ซึ่งเป็น
คนละเรื่องกับ "session ที่กดอยู่" — เกือบทุกครั้งมันคืออันเดียวกัน จนถึงวันที่ไม่ใช่
ปุ่ม ↻ จึงเคยโผล่ได้เฉพาะแถวที่จบล่าสุดของโฟลเดอร์+agent นั้น

- **ตั้งชื่อตั้งแต่ตอนเปิด** — provider ที่ให้ Orbit เลือกชื่อได้ถูกเปิดด้วย
  `claude --session-id <uuid>` และ ↻ ขอคืนด้วย `claude --resume <uuid>` แถวที่สาม
  นับจากล่าสุดจึงเปิดได้ตรงบทสนทนาที่กด
- **สิ่งที่แถวหนึ่ง "จอง" เปลี่ยนจากโฟลเดอร์เป็นบทสนทนา** — ยังกันเปิดซ้ำสองที่พร้อมกัน
  และกันไม่ให้ session ที่ resume แล้วจบ เสนอบทสนทนาเดียวกันจากสองแถว
- **session ที่ resume ขึ้นมา *คือ* บทสนทนานั้น** จึง resume ต่อได้อีก ส่วน ＋ (เปิดใหม่)
  มินต์ชื่อใหม่เสมอ
- **provider ที่ทำไม่ได้ยังใช้กติกาเดิม** — codex ยังเป็น "ล่าสุดของโฟลเดอร์" เหมือนเดิม

`~/.orbit` เดียวกันคือคนเขียน `sessions.json` สองคน และทุก session ในเทสถูกฆ่าทันทีที่

## 7. เทสที่โกหกมาตลอด กับ flag ที่ไม่เคยถูกลอง

ตอนจะพิสูจน์ข้อ 6 กับ Claude Code ตัวจริง เจอสองอย่างซ้อนกัน:

1. **`make test` ยัด PATH ให้ server ชั่วคราวไม่ได้** — scratch HOME ไม่มี `.zshrc`

   แล้วส่งต่อให้ server (login shell เก็บของที่สืบทอดมา)
2. **เทส agent resume เช็คผิดฟิลด์มาตั้งแต่ต้น** — มันดู `agent.resumable` ของ session

   ตามดีไซน์ (resume ตัวที่รันอยู่ = ยัด agent ตัวที่สองเข้าบทสนทนาเดียวกัน) เงื่อนไข

**skip ที่ไม่มีใครสงสัยคือเทสที่ตายแล้วแต่ยังนับว่าเขียวอยู่** — อันตรายกว่า FAIL

# ส่งงาน: รอบ "session ไหนรอเราอยู่" + แท็บ Changes (2 ส.ค. 2026, ค่ำ)

> **รอบนี้ต้องรีสตาร์ต server** — มีโค้ดฝั่ง server ใหม่ทั้งสองเรื่อง (`attention.ts`,
> `git.ts`, route ใหม่, `ORBIT_SESSION_ID` ใน env ของ PTY) หน้าเว็บอย่างเดียวไม่พอ
> agent ทำเองไม่ได้เพราะ session ที่ทำงานอยู่ใน PTY ของ server ตัวนั้น
>
> **`ORBIT_SESSION_ID` มีผลกับ session ที่เปิด _หลัง_ รีสตาร์ตเท่านั้น** — ของเก่า
> ไม่มีตัวแปรนี้ใน env จะตกไปใช้การเดาจากโฟลเดอร์ (ซึ่งใช้ได้เมื่อโฟลเดอร์นั้นมี
> session เดียว)

## 1. notice ไม่ใช่ toast ที่หายไปเฉย ๆ อีกแล้ว

ปัญหาเดิม: agent หยุดรอคำตอบ → toast ขึ้น 3 วิ → หายถาวร ถ้าไม่ทันเห็นก็ไม่เหลือ
ร่องรอยที่ไหนเลย และ push ที่กดเข้ามาก็พาไปหา session ที่เปิดค้างไว้ ไม่ใช่ตัวที่เรียก

- **`server/src/attention.ts`** เก็บข้อความล่าสุดต่อ session (`waiting` / `done`)
  ในหน่วยความจำ (session ที่รันอยู่ตายพร้อม server อยู่แล้ว ไฟล์จะโกหกได้อย่างเดียว)
  โผล่ใน `GET /api/sessions` ล้างด้วย `DELETE /api/sessions/:id/attention`
- **`done` ทับ `waiting` ไม่ได้** — Claude ถามเสร็จแล้วค่อยจบเทิร์นเป็นลำดับปกติ
  ถ้าปล่อยให้ทับ ป้ายจะกลายเป็น "เสร็จแล้ว" ทั้งที่คำถามยังไม่มีใครตอบ
- **`ORBIT_SESSION_ID` ใน `ptyEnv()`** — hook กับ MCP server เป็นลูกหลานของ PTY
  เลยได้มาเอง ไม่ต้องเดาจาก cwd อีก (cwd ยังเป็นทางสำรอง และ **ใช้ได้เฉพาะตอนที่
  โฟลเดอร์นั้นมี session รันอยู่ตัวเดียว** — ผิดตัวแย่กว่าไม่รู้เลย)
- **`quiet` เปลี่ยนความหมาย** จาก "มีมือถือต่ออยู่ไหม" เป็น "มือถือกำลังดู session
  **นี้** อยู่ไหม" มือถือรายงานเองผ่าน ws (`{type:'viewing'}`) ทุกครั้งที่สลับแท็บ
  และทุกครั้งที่แอปเข้า/ออก foreground ของเดิมทำให้ "Claude is waiting" ของอีก
  session หายไปเงียบ ๆ ระหว่างที่เรานั่งอ่านอันแรกอยู่
- **ฝั่งแอป**: ตัวเลขบนไอคอน Sessions (ทึบเมื่อมีตัวที่ `waiting`), ข้อความในแถว
  2 บรรทัด, toast ที่มาจาก session อื่นมีปุ่ม **Open** ในตัว, และ **การเปิด session
  นั้นคือการอ่าน** (ไม่ใช่การเปิดแอป ไม่ใช่การกด toast)
- **notification พาไปถูกที่**: payload พก `sessionId`, sw เปิด `/?session=<id>`
  ถ้ายังไม่มีหน้าต่าง และ `postMessage` ถ้ามี (WebKit ไม่ยอมให้ `navigate` client
  ของ PWA แบบ standalone)

**จุดที่พลาดตอนแรกและแก้แล้ว**: อ่าน `?session=` แล้วเคลียร์ทันที ทำให้ boot รอบแรก
(ที่ `setLocked` ยกเลิกทิ้ง) กินไป รอบสองเลยตกไปใช้ session ใน localStorage — ซึ่งคือ
ตัวที่ notification *ไม่ได้* พูดถึงพอดี ตอนนี้ค่าถูก "ใช้" โดยรอบที่ได้ลงมือจริงเท่านั้น

## 2. แท็บ Changes — อ่าน diff และ commit จากมือถือ

Terminal ตอบว่า agent กำลังทำอะไร Preview ตอบว่าแอปหน้าตาเป็นยังไง ไม่มีใครตอบว่า
**มันเขียนอะไรลงไป** — ทางเดียวคือ `git diff` ในเทอร์มินัลจอ 390px

- `server/src/git.ts` — status (พร้อมจำนวนบรรทัดต่อไฟล์), diff ต่อไฟล์ทั้งฝั่ง
  staged และ unstaged, stage/unstage, commit, push ทุกคำสั่งเป็น `git -C <cwd>` +
  array (ไม่ผ่าน shell) path ถูกกันทั้งออกนอก home และออกนอก repo
- ไฟล์ untracked นับบรรทัดและทำ diff โดยเทียบกับ `/dev/null` — มันไม่อยู่ใน index
  ให้ git เทียบ `--no-index` จบด้วย exit 1 เสมอ ซึ่งสำหรับที่นี่คือคำตอบ ไม่ใช่ error
- ตัด 4 บรรทัดหัว hunk ของ git ทิ้ง (`diff --git`, `index`, `---`, `+++`) — พูดซ้ำ
  กับชื่อไฟล์บนหัว sheet และกินพื้นที่ 1/5 ของหน้าจอแรก
- บรรทัดยาว **เลื่อนออกข้าง ไม่ตัดขึ้นบรรทัดใหม่** diff ที่ wrap แล้วดูไม่ออกว่า
  `+` อยู่คอลัมน์ไหน
- commit ใช้ `-m` ไม่มี `-a` — สิ่งที่เข้า commit คือสิ่งที่หมวด Staged แสดงเป๊ะ ๆ
- **Push โผล่เฉพาะตอนที่กดแล้วเกิดอะไรขึ้นจริง** (มี commit ค้าง หรือ branch ยังไม่เคย
  push → `--set-upstream` ให้เอง) repo ที่ไม่มี remote ไม่มีปุ่มนี้ ตอนทดสอบครั้งแรก
  ปุ่มขึ้นแล้วกดยังไงก็ error เลยเพิ่ม `hasRemote` เข้ามาใน status
- `GIT_TERMINAL_PROMPT=0` — git ที่จะถามรหัสผ่านไม่มีใครพิมพ์ให้ ปล่อยไว้มันจะค้าง
  จนหมดเวลาแล้วรายงานว่า "timeout" แทนที่จะบอกว่า remote ขอรหัสผ่าน

# ส่งงาน: รอบเก็บของหลังใช้จริงบนมือถือ (2 ส.ค. 2026, บ่าย)

> รอบนี้ไม่ต้องรีสตาร์ต — แก้ฝั่ง web ล้วน **reload หน้าเว็บบนมือถือหนึ่งครั้ง** พอ

**1. ปุ่ม Share กดไม่ติดบน PWA — ปุ่มเล็กเกินไป ไม่ใช่ share พัง** ผู้ใช้รายงานว่ากด
แล้วเงียบ วัดจริงด้วย Playwright ที่ 390×844: pill สูง **26.5px** แตะกลางเป๊ะติด แตะ
ต่ำกว่ากลาง **8px ไม่โดนอะไรเลย** — ไม่มี POST ไม่มี error ปุ่มยังอยู่ที่เดิม หน้าตา
เหมือนปุ่มเสียทุกประการ ขยายเป็น **44px** ตามที่ `ui.tsx` เขียนนิยามไว้เองแล้ว
(`lg = 44px, the minimum comfortable touch target` — ปุ่มนี้เขียนเป็น `<button>` ดิบ
เลยไม่ได้ใช้) วัดใหม่ 181×44 แตะเยื้อง ±14px ยังติดทุกครั้ง

ตัดออกไปด้วยหลักฐานระหว่างไล่: service worker ข้าม `/api/` ไม่ได้ cache (`sw.js`),
POST ผ่าน tailnet proxy กลับมาใน 0.26 วิ (สงสัยว่า `tailscale serve` ตัดสายของ
request ที่สั่งมันเอง — ไม่ใช่), และ mapping ที่ผู้ใช้กดติดยังอยู่จริงและ 200

**2. ลิงก์ที่ hostname ถูกย่อ ไม่ถูกเสนอเป็นลิงก์อีก** `https://...:8443/` (docs ของเรา
เองก็พิมพ์แบบนี้) เคยผ่านตัวหาลิงก์เพราะจุดกับโคลอนเป็น URL char แล้วกด Open here
ได้เฟรมเปล่า ตอนนี้ host ต้องเป็น label ที่ขึ้นและลงท้ายด้วย alphanumeric คั่นด้วยจุด
(หรือ IPv6 ในวงเล็บเหลี่ยม) `...` ไม่มี label ระหว่างจุดจึงไม่ match — ยังรับ userinfo
(`https://token@github.com/…`) ไว้ ไม่งั้น git remote จะเหลือแค่ `https://token`

**3. เอา 📷 ออกจาก header ของเฟรม** เจ้าของเครื่องถามว่ามีไปทำไม แล้วคำตอบไม่คุ้ม:
มันประหยัดได้แค่ *การปิดเฟรม* — รูปที่ถ่ายด้วยปุ่มข้าง+เพิ่มเสียงอยู่ใน Photos อยู่แล้ว

แถว 390px ที่ไม่มีอะไรบนจออธิบาย hardware gesture ที่มันต้องพึ่ง เหลือ ✕ ↻ ⧉ 🔗

**4. แท็บ Captures → Preview แล้วเก็บกวาดหน้านั้น** ชื่อเดิมเรียกแกลเลอรี ซึ่งเคย
เป็นทั้งหมดของแท็บนั้น ตอนนี้มันส่ง dev server ขึ้น https และเปิดสดทับ terminal ได้
ด้วย ภาพนิ่งกลายเป็นทางสำรอง เปลี่ยนชื่อทั้งใน UI และเอกสารที่ผู้ใช้อ่าน (ไม่แตะ
HANDOFF รอบเก่า — ตอนนั้นมันชื่อ Captures จริง ๆ) พร้อมกับ:

  ออกจากหน้าตัวเอง ส่วนแถวใต้มันเปิดแอปเดียวกันทับ terminal โดยไม่เสีย session

**สองชั้น** ที่ต้องเจอพร้อมกันถึงจะอธิบายได้ครบ:

1. Claude Code ตั้ง `?1000h ?1002h ?1003h ?1006h` (mouse tracking) — xterm.js
   ครอบ `handleTouchStart`/`handleTouchMove` ของตัวเองไว้ด้วย
   `if (!coreMouseService.areMouseEventsActive)` พอโหมดนี้เปิด xterm **ปิดการ
   เลื่อนด้วยนิ้วทิ้งทั้งหมด** แล้วส่ง touch ต่อให้แอปเป็น mouse event แทน ซึ่ง
   iOS ไม่สังเคราะห์จากการ *ลาก* นิ้ว → ไม่มีอะไรเกิดขึ้น
2. Claude Code ตั้ง `?1049h` (alt screen) ด้วย ถึง xterm ยอมเลื่อนก็ไม่มีอะไรให้
   เลื่อน — วัดได้ `scrollHeight 668 === clientHeight 668`

**กับดักตอน probe**: โหมดพวกนี้ **ไม่ได้ตั้งตอน start** เฟรมแรก ๆ เป็น output
ธรรมดา โหมดมาทีหลังตอน UI ของมันขึ้นครอง — probe ที่รัน 12 วิแล้วไม่พิมพ์อะไร
เห็นแค่ `?25 ?2004 ?2031 ?1004 ?2026` แล้วสรุปผิดว่าไม่มี alt screen ต้องรอ ~25 วิ
และป้อน input เข้าไปก่อน

**Claude Code รับ wheel event และเลื่อนทีละบรรทัด** — และนี่คือจุดที่รอบแรก
วัดผิดจนออกแบบผิด: probe ที่ **นับ byte ที่ตอบกลับ** วัดตอนอยู่ล่างสุด ซึ่งไม่มี
อะไรให้เลื่อนขึ้น เลยได้ `wheel → 0 byte` มาแล้วสรุปว่า "Claude Code เมิน wheel"
ทั้งที่ 0 แปลว่า *ไม่มีอะไรขยับ* ไม่ใช่ *ไม่รับคำสั่ง*

วัดใหม่ให้ถูก: render ด้วย `@xterm/headless` แล้วเทียบ**ข้อความบนจอ**ก่อน/หลัง
บน pane ที่เลื่อนได้จริงและอยู่ในทิศที่เลื่อนได้ (`/help` เป็น pane ที่มีตัวชี้
`↓`/`↑` มุมขวา — เปิดมาอยู่บนสุด ต้องทดสอบทิศ**ลง**) ที่ 12 แถวได้ผลชัด:

| ปุ่ม | ผลต่อหนึ่งครั้ง |
|---|---|
| PageDown | กระโดดทั้งหน้า |
| wheel down SGR `\x1b[<65;c;rM` | **1 บรรทัด** |
| Down arrow | 1 บรรทัด |

**แก้**: `web/src/Terminal.tsx` แยก `appOwnsScreen(term)` เป็น predicate ระดับ
โมดูล ใช้ร่วมกับ `pageScroll` (ปุ่ม ▲▼) จะได้ไม่แยกทางกันอีก แล้วให้ `onTouchMove`
แปลงระยะลากเป็น **wheel notch หนึ่งอันต่อหนึ่งบรรทัด** (`wheelReport`) เมื่อแอป
ครองจอ — 1:1 กับนิ้ว เศษที่ไม่ครบบรรทัดเก็บไว้รอ move ถัดไป และจำกัด 12 notch
ต่อ event กันน้ำท่วมตอนสะบัด ส่วนปุ่ม ▲▼ ยังเป็น PageUp/PageDown เพราะมันคือปุ่ม
"หน้า" ตามชื่อ เซสชัน shell ปกติปล่อยให้ xterm เลื่อน buffer ตัวเองเหมือนเดิม
ไม่งั้นเลื่อนซ้อนเป็นสองเท่า

**รอบแรกส่ง PageUp/PageDown ต่อครึ่งจอ** ผู้ใช้บอกทันทีว่า "ดูไม่เป็นธรรมชาติ" —
ถูกแล้ว นิ้วขยับแต่จอกระโดดทีละหน้า

**วิธีทดสอบซ้ำ** (probe เขียนสด ลบทิ้งแล้ว): ลอกโครงจาก `scripts/touch-smoke.mjs`
รันแอปที่เปิด `?1049h` + mouse tracking แล้วพิมพ์ทุก byte ที่ได้รับกลับออกจอ
(`node -e` ตัวเดียวพอ — แทน ESC ด้วยตัวอักษรก่อนพิมพ์ ไม่งั้นอ่านจาก
`.xterm-rows` ไม่ออก), ปัดด้วย `window.__touch` ระยะครึ่งจอ แล้วนับ `[<64;` /
`[<65;` ใช้ `ENGINE=webkit` — engine เดียวกับ iOS

ผลที่ได้: ลาก 330px = 21.7 บรรทัด → ส่ง 21 notch ทั้งสองทิศ พิกัดใน report เลื่อน
ตามนิ้ว ส่วน shell ปกติ scrollTop 5384 → 5054 (= 330px พอดี) โดยไม่มี report
หลุดออกไปเลย `make test-touch` ผ่านครบ

**บทเรียนที่ควรพกไป**: อย่าวัดว่า TUI "รับคำสั่งไหม" จากจำนวน byte ที่มันตอบ
ต้องวัดจากจอที่ render แล้ว และต้องอยู่ในสถานะที่คำสั่งนั้น *ทำอะไรได้* จริง

## รอบต่อ: กดค้างชิงนิ้วไป และการปัดไม่มีแรงส่ง

**สองอาการที่ผู้ใช้รายงาน**: (1) "ถ้านิ้วไปโดน text จะเลื่อนได้นิดเดียว แตะที่ว่าง
จะเลื่อนได้" (2) อยากได้ปัดเร็วแล้วไหลต่อและค่อย ๆ หยุด

**หมายเหตุ**: รอบนี้การปัดส่ง **wheel notch** (`\x1b[<64;col;rowM`) ไม่ใช่ PageUp
แล้ว — หนึ่งบรรทัดที่ลากได้คือหนึ่ง notch ทำให้เนื้อหาตามนิ้วแทนที่จะกระโดดทีละหน้า
ปุ่ม ▲▼ ยังเป็น PageUp เพราะมันคือปุ่ม "หน้า" (บันทึกเก่าที่ว่า Claude Code เมิน
wheel นั้นวัดตอนไม่มีอะไรให้เลื่อน จึงอ่านเป็น 0 byte — ไม่ใช่หลักฐานว่าเมิน)

**อาการ (1) ตัวจริง**: กดค้าง 420ms แล้วเลือกคำ ชิงทั้ง gesture ไป วัดได้ว่า
ปัดหลังหยุดนิ้ว 500ms → wheel notch = **0** และได้ selection 40 บรรทัดแทน
ที่ว่างไม่เป็นเพราะ `isBlankRow` ตัดออกก่อน — ตรงกับที่ผู้ใช้เห็นเป๊ะ

**ตัวแยกที่ใช้ไม่ได้ (ลองแล้ว ทั้งคู่ทำ `make test-touch` พัง)**:
- **ระยะทาง** — ลากเลือกลงไปท้ายจอโดยตั้งใจก็ไกลเท่ากันและเป็นแนวตั้งเหมือนกัน
- **ความเร็ว** — ลากเลือกวิ่งประมาณ 1.4 px/ms ส่วนปัดเลื่อน ~1.5 px/ms ทับกันสนิท

**ตัวแยกที่ใช้ได้**: *นิ้วเคลื่อนอยู่แล้วหรือเปล่าตอนคำสว่างขึ้น* คนที่ตั้งใจลาก
เลือกจะเห็นไฮไลต์ก่อนแล้วค่อยลาก (ในเทสต์คือนิ่ง 180ms หลังไฮไลต์ขึ้น) ส่วนคนที่
ตั้งใจเลื่อนคือนิ้วยังไม่เคยหยุด หน้าต่างจึงวัดจาก `selectedAt` และสั้น —
`RECLAIM_MS = 150` บวกเงื่อนไขกันสะดุด (เร็วพอ, ไกลพอ, เป็นแนวตั้ง)

**อาการ (2)**: ไม่มี scrollbar ให้ animate เพราะ pane เป็นของโปรแกรมปลายทาง แรงส่ง

## รอบต่อ: ย้าย selection ออกจาก terminal ไปเป็น panel

**สิ่งที่ผู้ใช้รายงานหลังรอบ RECLAIM ขึ้น production แล้ว** (server รีสตาร์ต
01:13:56, `sw.js` เป็น network-first จึงไม่ใช่ของค้าง cache): "แตะ text แล้วปัด
scroll แล้วหลุดไม่ scroll" — คือ heuristic ที่วัดได้ว่าผ่านในเทสต์ ยังไม่พอกับ
นิ้วจริง

**ข้อสรุป**: การแยก "กดค้างแล้วลากเพื่อเลือก" ออกจาก "พักนิ้วแล้วปัดเพื่อเลื่อน"
กลางท่า เป็นปัญหาที่ไม่มีคำตอบ ทั้งสองอย่างเป็นการเคลื่อนไหวเดียวกันจริง ๆ จนกว่า
นิ้วจะหยุด รอบนี้เลยเลิกตัดสิน แล้วเปลี่ยนโครงแทน

**สองอย่างที่เปลี่ยน**

1. **กดค้างไม่ทำอะไรตอนครบเวลา — แค่ arm แล้วสั่น** panel เปิดตอน *ยกนิ้ว* และ
   เฉพาะเมื่อนิ้วไม่เคยออกนอก `TOUCH_SLOP_PX` นิ้วที่ขยับแปลว่าเลื่อน ไม่มี
   ข้อยกเว้น `RECLAIM_MS` / `RECLAIM_VELOCITY` / `RECLAIM_LINES` ถูกลบทิ้งทั้งชุด
   เพราะไม่เหลืออะไรให้ชิงคืน
2. **selection ไม่เกิดบน terminal อีกแล้ว** `terminal-selection.ts` (234 บรรทัด:
   grip, rect, cell range, drag) ถูกลบ แทนด้วย `terminal-snapshot.ts` +
   `sheets/SelectSheet.tsx` — snapshot แช่แข็ง buffer เป็น `<pre>` ข้อความจริง
   แล้วปล่อยให้ selection ของ OS ทำงาน (แว่นขยาย, handle, double-tap, Look Up,
   Share) พร้อม pre-select คำที่กดค้างด้วย `setBaseAndExtent` ท่าเดียวจบเหมือนเดิม

**ทำไม snapshot ถึงจำเป็น ไม่ใช่แค่ดีกว่า**: `term.onScroll` เคยต้องทิ้ง selection
ทุกครั้งที่ buffer เลื่อน และ Claude Code อยู่บน alt screen ที่ repaint แทบทุกเฟรม
— การเลือกข้อความระหว่างมันทำงานเป็นไปไม่ได้เชิงโครงสร้าง ของที่ไม่ขยับเท่านั้น
ที่ selection อยู่ได้

**สิ่งที่เก็บไว้**: bar เดิม (นับ chars/lines + Copy) ยังอยู่สำหรับ **เมาส์บน
desktop** เพราะ selection ของ xterm เองไม่มีเมนู ไม่มี shortcut นิ้วไม่เคยไปถึงมัน

**กับดักที่ต้องระวังถ้าแตะ `SelectSheet`**
- container ของ terminal ตั้ง `[-webkit-user-select:none]` +
  `[-webkit-touch-callout:none]` ไว้ panel ต้องเปิดกลับทั้งคู่ ไม่งั้นเมนู native
  ไม่ขึ้นเลยและจะดูเหมือน panel เสีย — มีเทสต์คุมไว้แล้ว
  ("and the text is selectable by the platform")
- `<pre>` ต้องเป็น **text node เดียว** DOM offset จะได้เท่ากับ string offset ซึ่ง
  คือสิ่งที่ทำให้ pre-select และปุ่ม Line ทำงานโดยไม่ต้องทำดัชนี span
- `white-space: pre` + เลื่อนออกข้าง ไม่ wrap — ตรงกับแท็บ Changes การ wrap ใหม่ที่
  390px จะทำให้บรรทัดที่ก๊อปไม่ตรงกับบรรทัดบนจอ และพัง diff/ตาราง
- ปุ่ม Copy เก็บ **ข้อความที่ก๊อป** (`copiedText`) ไม่ใช่ boolean — boolean ค้างเป็น
  "Copied" ข้ามการเปลี่ยน selection เพราะลำดับ `selectionchange` ไม่แน่นอน

**เทสต์ที่เพิ่ม** (`scripts/touch-smoke.mjs`, ผ่านทั้ง chromium และ webkit):
กดค้างเปิด panel พร้อมคำที่ถูกเลือก / ข้อความ selectable จริง / path ไม่ถูกตัดที่ `/`
/ Line ได้ทั้ง logical line ที่ wrap / panel ถือ scrollback (201 บรรทัด เทียบ 44
บนจอ) / ที่ว่างไม่เปิดอะไร / **กดค้างแล้วปัด → ไม่เปิด panel และเลื่อนจริง
(2355 → 2115)** / และเคสตัวจริง: โปรแกรมที่เปิด `?1049h` + mouse tracking กดค้าง
แล้ว panel ยังเปิดและถือเฟรมที่เห็นอยู่

**ที่ต้องยืนยันบนเครื่องจริงหลังรีสตาร์ต**
- กดค้างบนคำใน `claude` แล้วยกนิ้ว → panel เปิด คำนั้นถูกเลือก handle ของ iOS ขึ้น
- ลากขยาย/บีบ selection ด้วย handle → ต้องได้เมนู Copy / Look Up ของระบบ
- พักนิ้วบน text นานแล้วปัด → ต้องเลื่อน ไม่มี panel เด้ง
- ปิด panel แล้วพิมพ์ต่อ → คีย์บอร์ดกลับมาปกติ

ที่ไขคดีทั้งหมด — **"แต่ touch บนที่ว่าง scroll ได้"**

**สาเหตุ**: touch หนึ่งครั้งเป็นของ node ที่มันเริ่ม ตลอดอายุของมัน ถ้า node นั้น
หลุดออกจาก document event ที่เหลือ *ยังวิ่งไปหามันเหมือนเดิม* — บน node ที่ detach
แล้ว ซึ่งไม่มีทาง bubble ขึ้นมาถึง listener บน `term.element` ได้อีก และ DOM
renderer ของ xterm **สร้าง `<span>` ของแถวใหม่ทุกครั้งที่แถวนั้นเปลี่ยน** นิ้วที่ลง
บนตัวอักษรจึงถือ node ที่ตายไปแล้วภายในเฟรมเดียวที่แอปวาดใหม่ ส่วนนิ้วที่ลงบนแถว
ว่างถือ div เปล่าที่ไม่มีใครเขียนทับ จึงรอด — ตรงกับที่ผู้ใช้เห็นทุกตัวอักษร

**ผลวัด** (WebKit 390×844, ปัด 20 move จากแถวเดียวกัน):

| นิ้วเริ่มบน | node ที่ถือ | move ที่ไปโดน node ตาย | wheel notch ที่ส่งได้ |
|---|---|---|---|
| ตัวอักษร (ก่อนแก้) | `<span>` | 19/20 | **1** |
| ที่ว่าง (ก่อนแก้) | `<div>` | 0/20 | 28 |
| ทั้งสองที่ (หลังแก้) | `.xterm-screen` | 0/20 | 27–28 |

**แก้**: `[&_.xterm-rows]:pointer-events-none` บน container ของ terminal เฉพาะ
เครื่อง touch — เอาแถวออกจาก hit-test นิ้วเลยไปลงบน `.xterm-screen` ซึ่ง `open()`
สร้างครั้งเดียวและไม่เคยเปลี่ยน ไม่เสียอะไรเลยเพราะทุก gesture ในไฟล์นี้หา cell
จากพิกัดอยู่แล้ว ไม่ได้ใช้ `e.target` ส่วนเมาส์ยังได้แถวไว้ให้ xterm ทำ hover/click
ของมันเอง

**ทำไมเทสต์เดิมมองไม่เห็น** — และนี่คือบทเรียนหลักของรอบนี้: `window.__touch` ใน
`touch-smoke.mjs` หา target ใหม่ด้วย `elementFromPoint` **ทุก move** ซึ่งซ่อมท่าที่
นิ้วจริงซ่อมไม่ได้ให้เงียบ ๆ ทุกรอบ ตอนนี้เพิ่มโหมด `'hold'` ที่ยึด node แรกไว้
เหมือนเบราว์เซอร์จริง และ `ALT_APP` ในเทสต์ถูกทำให้ **repaint ทุก 120ms** ด้วย —
แอปที่วาดครั้งเดียวแสดงบั๊กนี้ไม่ได้เลย ยืนยันแล้วว่าเทสต์ใหม่ FAIL ถ้าถอด fix ออก
(19/20 detached, 1 notch) และ PASS เมื่อใส่กลับ (0/20, 28 notch)

**บทเรียนที่ควรพกไป**: ถ้าอาการต่างกันระหว่าง "บนตัวอักษร" กับ "บนที่ว่าง" ให้
สงสัย identity ของ DOM node ก่อนเสมอ ไม่ใช่พิกัด — พิกัดถูกตัดออกไปแล้วรอบนี้ด้วย
การวัดว่า claude เลื่อนเท่ากันหมดไม่ว่าจะใส่ row ไหนใน wheel report (แถว 10/27/29
→ 24/23/23 แถวเปลี่ยนเท่ากัน)

## ที่ต้องยืนยันบนเครื่องจริงหลังรีสตาร์ต (รอบ glyph target)

- ปัดจาก**บนตัวอักษร**ในเซสชัน claude — ต้องเลื่อนได้สุดทางเท่ากับปัดจากที่ว่าง
- กดค้างบนตัวอักษรแล้วยกนิ้ว — panel ต้องยังเปิด และ pre-select คำเดิม
- แตะลิงก์ — ต้องยังเปิดได้ (hit-test เป็นพิกัด ไม่ได้ใช้ target แต่ควรลองจริง)
- เซสชัน shell — ปัดต้องยังเลื่อน buffer ของ xterm ได้เหมือนเดิม
